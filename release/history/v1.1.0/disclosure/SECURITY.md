# Security and disclosure

Do not place credentials, private proof objects, personal records, or exploitable details in a public issue.

Use a private reporting channel confirmed by the maintainers before sending sensitive details. This preparation does not claim that GitHub private vulnerability reporting is enabled or promise a response deadline.

A useful report identifies the public package and version, affected proof or access boundary, expected and observed behavior, and a minimal synthetic reproducer. Preserve source evidence without publishing someone else’s artifact.

The disclosure inventory checker is not an artifact verifier. Its manifest is unsigned. Report inconsistencies separately from a proof-authentication bypass so the evidence remains precise.
